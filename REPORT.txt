# Proxy List Sources - Test Report

Date: 2026-11-02
Task: verify which of the listed sites actually return proxy lists (any protocol),
and collect every entry into one text file.

Deliverables in this directory
------------------------------
  lists.json        machine-readable source registry: verdict, working feed URLs,
                    cached filename, line format, entry count per feed
  all_proxies.txt   2,203,284 unique entries, one per line (87 MB)
  collect.py        parser that turns sources/* into all_proxies.txt (rerunnable)

gfpcom/free-proxy-list                     WORKS, DATA IS NOT IN THE REPO
  github: https://github.com/gfpcom/free-proxy-list
  IMPORTANT: the repo's `sources/*.txt` files are UPSTREAM FEED URLS, not proxies
  (they list other repos' raw URLs, some with a `,base64,` or `,mtproto` tag
  appended). Parsing them as proxies yields garbage.
  The generated output lives in the repo WIKI, reachable over the raw endpoint:
    https://raw.githubusercontent.com/wiki/gfpcom/free-proxy-list/lists/<PROTO>.txt
  Counts observed 2026-11-02 (total advertised: 2,202,985):
    http 551,580 | https 503,541 | socks4 489,088 | socks5 505,829 | vless 94,085
    trojan 24,329 | vmess 14,656 | ss 13,965 | tg 2,666 | hy2 2,463 | ssr 302
    tuic 261 | wireguard 94 | anytls 19 | hy 68 | less 1 | socks 38
  Format: scheme-prefixed URIs, e.g. `socks5://ip:port`,
  `vless://<uuid>@host:443?path=%2F...&security=tls#Name`,
  `tg://proxy?port=443&secret=ee...&server=host`,
  `wireguard://<pubkey>@host:port`. Lines may carry a URL-encoded `#Name` fragment.
  This is by far the largest source (it aggregates hundreds of feeds, including
  several of the other repos in this report), and drives the total count.

============================================================================
2. OUTPUT FILE: all_proxies.txt
============================================================================
  2,203,284 unique lines from 2,268,826 parsed entries (65,542 duplicates dropped).
  One entry per line. Two shapes, on purpose:
    <scheme>://<host>:<port>            for tcp proxies (http/https/socks4/socks5)
    <scheme>://<params>@<host>:<port>   for tunnel URIs (vless/vmess/trojan/ss/ssr/
                                         tg/hy2/tuic/wireguard) - kept verbatim,
                                         including any #fragment
  Entries carrying credentials appear as `scheme://user:pass@host:port`
  (135,830 lines contain `@`).
  Sorted by scheme, then host.

  Protocol totals:
    http        551,662      vless      94,082      tg        2,666
    socks5      506,134      trojan     24,325      hy2       2,463
    https       503,583      vmess      14,656      ssr         302
    socks4      489,091      ss         13,965      tuic        261
                                           wireguard    94

  Overlap warning: gfpcom already aggregates TheSpeedX, Proxifly, roosterkid and
  others, so the "unique" number is only unique by string, not by owner/operator.
  If you want independence-per-source, weight sources rather than counting lines.

============================================================================
3. NOTES FOR THE AUTOMATION AGENT
============================================================================
  - Branch names differ: `main` for ProxyScrape, hideip.me, monosans, jetkai,
    gfpcom, roosterkid; `master` for TheSpeedX and vakhov. Do not hardcode one.
  - Prefer the JSON feeds (monosans proxies.json, jetkai proxies.json,
    vakhov proxylist.json, ProxyScrape data.json) - they carry protocol + auth +
    geo, which the TXT feeds do not.
  - Protocol-less TXT (jetkai proxies.txt, vakhov proxylist.txt) cannot be merged
    safely into a labelled corpus; skip them or join against the JSON.
  - Fetch via the raw.githubusercontent.com / cdn.jsdelivr.net endpoints only;
    HTML pages and the /blob/ URLs return markup.
  - gfpcom wiki lists are individually multi-MB (vless.txt was 22 MB). Fetch in
    parallel with a streaming write and expect ~90 MB total per run.
  - Dedup key: normalize scheme to lowercase, host to lowercase, keep port. Do
    NOT dedupe tunnel URIs by host:port alone - the credentials/uuid are the point.
  - Keep per-source counts in the run log; a source that drops to zero is how you
    detect an upstream layout change (that is exactly how the dead ProxyScrape
    URL in the original prompt was found).
  - Re-run: refresh sources/ with the URLs in lists.json, then `python3 collect.py`.
